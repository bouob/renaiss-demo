project-renaiss — Merchant Copilot

Renaiss＝市場基礎設施 · Dokipoki＝商家智慧層 · 真相源 PLAN.md · 2026-07-11
一句話：Dokipoki 把 Renaiss 市場資料變成商家決策——該推什麼、該留什麼、該出清什麼。

兩版遞進

Version A — Merchant Copilot（MVP，市場端、免登入可用）
只回答「現在該推哪些卡、為什麼」。市場指數脈絡 + movers 排名 + alpha/相對強度 + promote/clear 建議 + 可解釋理由。不需要庫存、不需要登入。
Version B — + 輕量庫存層（延伸）
同一套邏輯套在店家實際持有的卡上——你的庫存誰該 Push/Hold/Clear。Firebase 登入後以 uid 管理；錢包掃描 / 手動 cert 匯入。

為何市場端先做（不是把庫存降級）：四層本身就是相依順序——L2「你的庫存上榜了」、L3 庫存 alpha，在沒有 L1 市場/指數引擎前根本算不出來。市場先做＝由下往上建那些訊號的地基。

產品分層（＝相依順序）

層內容用途
L1 市場脈絡指數 tile + sparkline + deltas（可選近期交易 ticker）今天什麼行情
L2 庫存相關性movers ∩ 店家庫存；在庫值得關注的卡市場連到能賣的卡
L3 相對智慧alpha badge、庫存 vs 市場圖、超額/落後分辨真強勢 vs 大盤帶動
L4 商家行動Promote / Feature / Hold / Clear訊號變動作

Version A ＝ L1+L3+L4（市場端）；Version B 加 L2（吃庫存）。

硬限制

⚠️ Renaiss FMV 用 graded cert 查
getGradedFmv(cert) 是「已鑑定卡」的價。加入庫存 = cert 導向（掃描 / 手動 cert / 拍鑑定殼序號）。PokeTrace 搜尋拿不到 Renaiss FMV，不重搬。raw 未鑑定散卡完全不列入，本版 graded-only。估值只給 Renaiss API 有資料的卡：found:false → 標記「無 Renaiss 資料」，不猜價、不 fallback。

關聯卡片探索（cert-based）· Dokipoki 已實作

相連認證公司號碼鑑定卡：給一個 cert，找同鑑定公司 cert ±1 的相鄰鑑定卡（renaissCertAdjacency PSA/CGC/BGS ±1 → getGradedCardBrief）＋ cert→卡片本身解析。Dokipoki 已上線（/api/renaiss/adjacent-cert），低風險直接移植。散卡不適用。

⚠️ gating 必須
任意 cert 查詢會耗盡與 getGradedFmv 共用的 quota/breaker → 癱瘓估值。/related/:cert 僅服務庫存內/已掃描的 cert或至少 IP-rate-limit；非持有 cert 回空、不打上游；只快取真空結果。

合併：衝突與調整（outline ↔ PLAN）

方向高度一致。以下為對照後的實質調整；待裁決 兩項可否決。

已套用 1. MVP 順序翻轉：outline 明示「Version A first」。原本錢包掃描/庫存排 P1（最高風險），改市場端先行（P1 指數、P2 movers），庫存移 P3+。

已定 2. raw vs graded ＝ graded-only：FMV 只吃 graded cert，raw 卡無法定價。demo 用 10 置頂 + 錢包掃描皆 graded NFT，足夠。承認缺口：raw 散卡需 PokeTrace，列 backlog。

已調整 3. MVP gate 前移：index payload 豐富度是 MVP 成敗關鍵。拿到 key 先驗（待驗證 #1）再寫 movers：topMovers 是否每卡帶 7d/30d change？（無→每卡 series 進 P2 關鍵路徑）是否有流動性訊號？（無→退化 delta+alpha）

已調整 4. scoring 引擎可選：movers 用簡單 7d/30d delta + alpha + 流動性門檻即可，不強制搬 server/scoring/。

對齊 5. 近期交易 ticker＝demo enhancer（P6）；scan-to-FMV＝cert 讀取 intake（非 Dokipoki 緩做的 by-image）；持倉上榜/組合 vs 市場＝collector→merchant 換主詞。

additive 6. 庫存輸入加 CSV 匯入、quantity 欄位。
